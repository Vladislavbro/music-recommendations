## Постановка задачи

Работа посвящена построению системы коллективных (групповых) музыкальных рекомендаций для сценария **физически локализованных эфемерных групп** — посетителей заведений (кафе, баров, фитнес-клубов) и участников мероприятий, спонтанно собирающихся вместе и не имеющих длительной истории совместных прослушиваний. Целевой результат системы — групповой плейлист, одновременно учитывающий вкусы всех присутствующих участников и сохраняющий справедливость распределения «выгоды» между ними.

Содержательно задача декомпозируется на два уровня:

1. **Персональный уровень.** Для каждого участника группы строится последовательная модель ранжирования, оценивающая релевантность треков на основании индивидуальной истории прослушиваний.
2. **Групповой уровень.** Поверх персональных скоров применяется агрегатор, отображающий множество индивидуальных оценок в финальный групповой список рекомендаций.

Архитектурно система реализуется как многоэтапная воронка (candidate generation → pre-ranking → sequential ranking → group aggregation), типичная для промышленных рекомендательных платформ. В качестве источника данных используется датасет **YAMBDA (Yandex Music)**, опубликованный в 2025 году: 4,79 миллиарда взаимодействий, 1 миллион пользователей, 9,4 миллиона треков, плюс предобученные аудиоэмбеддинги треков и флаг органичности взаимодействия `is_organic`.

## Научный вклад и гипотезы

Основной научный вклад работы сосредоточен на уровне **групповой агрегации**. Предлагается семейство **audio-aware attention-агрегаторов**, использующих аудиоэмбеддинги YAMBDA вместо обучаемых ID-эмбеддингов треков, характерных для существующих нейросетевых подходов к групповым рекомендациям (AGREE, GroupIM, AlignGroup). Замена ID-сигнала на содержательный аудиосигнал решает проблему деградации качества на редких и новых треках («длинном хвосте» каталога) и вводит в групповой агрегатор класс информации, не использовавшийся в существующих работах по теме.

Семейство представлено тремя вариантами возрастающей архитектурной сложности:
- **Audio taste profile** — необучаемый агрегатор на косинусном сходстве аудиопрофилей пользователей с аудиоэмбеддингом кандидата;
- **Audio-AGREE** — обучаемый attention поверх аудиопрофилей и аудиоэмбеддинга кандидата (прямой аналог AGREE с заменой $e_i \to a_i$);
- **Group cross-attention** — multi-head cross-attention с членами группы как ключами и значениями.

В работе проверяются две центральные гипотезы:

- **H1 (преимущество audio-aware агрегации).** Предложенное семейство превосходит классические необучаемые стратегии (Average, Least Misery, Max Pleasure) и современные обучаемые бейзлайны для эфемерных групп (ID-based AGREE, GroupIM) по основным групповым метрикам (Group-NDCG@K, Jain@K и их сводной мере DFH@K).
- **H2 (роль архитектурной сложности агрегатора).** В пределах audio-aware семейства качество монотонно растёт с усложнением архитектуры: group cross-attention $>$ Audio-AGREE $>$ audio taste profile.

Дополнительно проводится анализ срезов по типу группы (гомогенные/гетерогенные/случайные) и по доле редких треков в множестве кандидатов (cold-start срез) — для содержательной интерпретации источников выигрыша.

## Экспериментальный протокол

- **Датасет:** YAMBDA (Yandex Music, 2025).
- **Per-user скорер:** трёхэтапная воронка ALS + HNSW $\to$ лёгкий CatBoost $\to$ gSASRec, фиксируется на этапе обучения и не подвергается ablation, чтобы изолировать вклад группового агрегатора.
- **Групповой уровень:** сравниваются восемь стратегий — AVG, Least Misery, Max Pleasure, ID-based AGREE, GroupIM и три варианта audio-aware агрегатора. Обучаемые модели тренируются на синтетических случайных группах с pairwise BPR-loss и popularity-based негативным семплированием.
- **Метрики:** Group-NDCG@K, Jain@K, сводная DFH@K, вспомогательная Disagreement@K — на общем срезе и на cold-start подвыборке. Доверительные интервалы — бутстрап по группам ($N = 1000$).
- **Вычислительные ограничения:** Google Colab, A100, не более нескольких часов на конфигурацию.
