## Постановка задачи

Работа посвящена построению системы коллективных (групповых) музыкальных рекомендаций для сценария **физически локализованных эфемерных групп** — посетителей заведений (кафе, баров, фитнес-клубов) и участников мероприятий, спонтанно собирающихся вместе и не имеющих длительной истории совместных прослушиваний. Целевой результат — групповой плейлист, одновременно учитывающий вкусы всех присутствующих и сохраняющий справедливость распределения «выгоды» между ними.

Содержательно задача декомпозируется на два уровня:

1. **Персональный уровень.** Для каждого участника группы строится последовательная модель ранжирования, оценивающая релевантность треков на основании индивидуальной истории прослушиваний.
2. **Групповой уровень.** Поверх персональных скоров применяется агрегатор, отображающий множество индивидуальных оценок в финальный групповой список рекомендаций.

В качестве источника данных используется датасет **YAMBDA (Yandex Music)**, опубликованный в 2025 году: 4,79 миллиарда взаимодействий, 1 миллион пользователей, 9,4 миллиона треков, плюс предобученные аудиоэмбеддинги треков (`d_a = 128`) и флаг органичности взаимодействия `is_organic`. В экспериментах используется flavor `50m`.

## Научный вклад и гипотеза

Основной вклад работы сосредоточен на уровне **групповой агрегации**. Предлагается семейство **audio-aware attention-агрегаторов**, использующих аудиоэмбеддинги YAMBDA вместо обучаемых ID-эмбеддингов треков, характерных для существующих нейросетевых подходов к групповым рекомендациям (AGREE, GroupIM, AlignGroup). Замена ID-сигнала на содержательный аудиосигнал решает проблему деградации качества на редких и новых треках («длинном хвосте» каталога) и вводит в групповой агрегатор класс информации, не использовавшийся в существующих работах по теме.

Семейство представлено двумя обучаемыми вариантами:
- **Audio-AGREE** — attention поверх аудиопрофилей и аудиоэмбеддинга кандидата (прямой аналог AGREE с заменой $e_i \to a_i$).
- **Group Cross-Attention** — multi-head cross-attention с членами группы как ключами и значениями.

**Центральная гипотеза.**

> **H1.** При фиксированном per-user скорере (SASRec) audio-aware агрегаторы превосходят классические необучаемые стратегии (Average, Least Misery, Max Pleasure) и современные обучаемые ID-бейзлайны для эфемерных групп (AGREE, GroupIM) по групповым метрикам NDCG@K.

## Метод

### Per-user скорер (Phase 1)

**Plain SASRec + BCE-loss**, конфиг яндексовский: `hidden_dim=64, n_heads=2, n_layers=2, n_neg=1, mix_uniform=1.0, max_seq_len=200`. На YAMBDA-50m gBCE-loss не дала выигрыша (см. [logs/PHASE_1_LOG.md](logs/PHASE_1_LOG.md)) — используется plain BCE.

| Метрика | Наш SASRec | Yandex baseline |
|---|---:|---:|
| Test NDCG@10 (Listen+) | **0.0726** | 0.0742 |

Чекпоинт скорера — `artifacts/gsasrec/best.pt`; на Phase 2 он **заморожен** и обучаются только параметры агрегатора. Топ-K скоров кэшируются (`artifacts/user_scores_cache/scores.parquet`, K=200), поэтому групповые эксперименты не дёргают скорер на каждом батче.

### Групповые агрегаторы (Phase 2)

| Метод | Тип | Источник | Реализация |
|---|---|---|---|
| AVG | необучаемый | классика | `src/eval/group_eval.py` |
| Least Misery (LM) | необучаемый | классика | `src/eval/group_eval.py` |
| Max Pleasure (MP) | необучаемый | классика | `src/eval/group_eval.py` |
| AGREE (ID-based) | обучаемый | Cao et al., SIGIR'18 | [src/aggregators/agree.py](src/aggregators/agree.py) |
| GroupIM | обучаемый | Sankar et al., SIGIR'20 | [src/aggregators/groupim.py](src/aggregators/groupim.py) |
| **Audio-AGREE** | обучаемый | предложено в работе | [src/aggregators/audio_agree.py](src/aggregators/audio_agree.py) |
| **Group Cross-Attention** | обучаемый | предложено в работе | [src/aggregators/group_cross_attn.py](src/aggregators/group_cross_attn.py) |

**AlignGroup** не включён: гиперграф требует persistent-групп, а alignment-loss — совместного обучения с per-user веткой; обе предпосылки нарушаются на YAMBDA-эфемерных группах.

### Экспериментальный протокол

- **Группы.** Синтетические random-группы из train-пула пользователей; размеры 2–5 с распределением `{2: 0.3, 3: 0.4, 4: 0.2, 5: 0.1}` (split хранится в `artifacts/groups_split.pkl`).
- **Кандидаты.** `C_G` = union top-K (`K = 200`) каждого члена группы из кэша скорера.
- **Targets.** Union test-listens членов ∩ `C_G`.
- **Loss.** Pairwise BPR с popularity-weighted негативами из `C_G \ targets`.
- **Метрики.** NDCG@10/20 на 2000 test-групп; 95% доверительные интервалы — bootstrap по группам (1000 ресэмплов, общая resample-сетка для всех методов, paired-тест аудио vs ID).
- **Аудиоэмбеддинги.** Subset на 276k items, ~135 MB (`artifacts/audio/embeddings.npy`); coverage 95.85% (4.15% catalog drift маскируется через нулевые векторы).

### Важная оговорка интерпретации

Phase 2 сравнивает **агрегационные механизмы поверх фиксированного SASRec**, а не полные пайплайны AGREE / GroupIM (в оригинальных работах per-user скорер обучается совместно с агрегатором). Наша рамка изолирует вклад агрегационного механизма при едином двухстадийном retrieve-rerank сетапе, типичном для индустриальных рекомендательных систем.

## BLE Scanner Demo

В директории [BLE_scanner_demo/](BLE_scanner_demo/) лежит вспомогательное Android-приложение — демонстрация того, как в продакшен-сценарии формируется эфемерная группа: посетители заведения определяются по присутствию в зоне действия BLE-маяков (танцпол, бар и т.п.), и состав группы динамически обновляется по силе сигнала. Это иллюстрация того, *откуда берётся* множество членов группы для агрегатора — сам ML-пайплайн от приложения не зависит.

Подробности сборки и использования — в [BLE_scanner_demo/README.md](BLE_scanner_demo/README.md).
