# Резонанс (демонстрация)

Локальный HTML-прототип для демонстрации ВКР: движение посетителей клуба, BLE-имитация местоположения и формирование групп `user_id` для коллективных музыкальных рекомендаций.

## Запуск

Из папки проекта:

```bash
python -m http.server 8000
```

Откройте в браузере:

```text
http://localhost:8000
```

Важно запускать через локальный сервер, а не через `file://`, потому что браузер может запретить чтение файла со списком `user_id`.

## Нужные файлы

```text
assets/club_map.svg
data/yambda_50m_unique_user_ids.txt
```

`club_map.svg` используется как готовая схема клуба и не перерисовывается кодом. Посетители, BLE-маяки, подписи и debug-маршруты накладываются отдельным SVG-слоем поверх карты.

`yambda_50m_unique_user_ids.txt` читается как построчный список уникальных `user_id`. Один идентификатор назначается только одному посетителю и не возвращается после выхода.

## Где менять настройки

Все основные параметры находятся в начале `app.js`.

- Вместимость клуба: `CONFIG.clubCapacity`, а также константа `CLUB_CAPACITY`.
- Лимит веранды: `CONFIG.maxVerandaShare`.
- Лимит WC: `CONFIG.maxToiletShare`.
- Координаты зон: объект `ZONES`.
- Координаты BLE-маяков: объект `BEACONS`.
- Маршрутные точки: объект `WAYPOINTS`.
- Схемы маршрутов: объект `ROUTES`.
- Скорость входа, размер очереди и интервалы обновлений: объект `CONFIG`.

Правила поведения посетителей находятся в функциях:

- `chooseNextZone(agent)` - выбор следующей зоны;
- `canEnterZone(zoneName)` - проверка лимитов веранды и WC;
- `getZoneOccupancy(zoneName)` - расчет занятости зоны;
- `startLeaving(agent)` - запуск сценария выхода;
- `shouldLeave(agent)` - вероятность финального решения уйти;
- `getDwellTime(agent, zoneName)` - время пребывания в зоне.

Маршруты строятся функцией `buildRoute(fromZone, toZone)`. Для ручной подгонки координат включите в интерфейсе `Debug: координаты и маршруты`; он показывает координаты курсора, центры зон, текущий `viewBox`, активный маршрут выбранного посетителя и количество активных агентов.

## BLE и группы

Для каждого активного посетителя рассчитываются RSSI/dBm-сигналы от четырех маяков:

- `entrance`;
- `bar`;
- `dancefloor`;
- `veranda`.

Местоположение определяется по трем самым сильным сигналам: RSSI переводятся в примерные расстояния, затем дополнительно сравнивается RSSI-профиль с набором точек внутри каждой зоны. Это делает детекцию устойчивее для крупных зон, где посетитель может быть далеко от центра маяка. Уверенность по-прежнему считается как разница между самым сильным и вторым сигналом: `confidence = strongestRssi - secondStrongestRssi`.

Физическая точка входа/выхода задается в `WAYPOINTS.entranceDoor` и находится в проеме нижней стены. BLE-маяк `BEACONS.entrance` остается отдельной точкой сигнала и не используется как дверной проем.

Функция `getRecommendationGroups()` возвращает:

- `centralRoomGroup` - пользователи, у которых `detectedLocation === "bar"` или `detectedLocation === "dancefloor"`;
- `dancefloorGroup` - пользователи с `detectedLocation === "dancefloor"`;
- `barGroup` - пользователи с `detectedLocation === "bar"`;
- `verandaGroup` - пользователи с `detectedLocation === "veranda"`.

## Рекомендации

Сейчас блок рекомендаций использует mock-логику:

```js
function getMockRecommendations(userIds) {
  ...
}
```

Точка подключения реальной модели:

```js
async function fetchRecommendationsFromBackend(userIds) {
  // later: POST /recommend
}
```

В этой функции можно заменить mock на запрос к Python backend, который принимает массив `user_id` и возвращает список `track_id`.
